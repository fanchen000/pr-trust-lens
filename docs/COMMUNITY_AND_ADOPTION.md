# Community participation and honest adoption evidence

We welcome maintainers running AI coding agents in GitHub Actions, security
engineers, and owners of open-source repositories. This project is early-stage
and does **not** claim established adoption.

## What helps most

- Minimal sanitized examples where a rule reports a false positive or
  misses a supported trust boundary (remove keys and private context).
- Small fixes with a failing regression test and offline verification.
- Reproducible public downstream CI integrations or release references.
  Open an issue with a public link and permission to list your project.
- Documentation and compatibility reports.

## Evidence accounting policy

| Category | What counts | What never counts |
|---|---|---|
| Project maintenance | Actual reviewed changes, tests, releases, resolved issues | Plans or self-written status labels |
| External evaluation | Pinned public third-party code scanned read-only, with limits | Presenting those scans as user installs |
| Independent contributions | PRs/issues authored by a nonowner, reviewed on merit | Owner self-issues relabeled as third-party |
| Independent adoption | Public downstream installation or CI example with source link | Stars, views or clones equated with active use |
| Downloads | Verified registry/release counters with date and source | Fabricated package downloads |

We prefer project usefulness and accuracy over inflating metrics for OSS
funding applications. Questions and design proposals are welcome in GitHub
Discussions if enabled; actionable bugs belong in Issues.
